# Allocator-war frozen source structural parses Wave 33

Wave 33 consumes only the nineteen permanent Wave 32 snapshot rows and their frozen response bytes. It does not issue network requests. Before parsing a response, the builder verifies the committed byte count and SHA-256 digest against the Wave 32 snapshot ledger.

Seven JSON snapshots are parsed with deterministic recursive traversal. The parser records root type, object and array counts, scalar-type counts, maximum depth, key frequencies, bounded array paths, and declared candidate-array shape signatures. Field names are preserved as structural keys, while field values are not promoted into source semantics, affected populations, actions, comparators, remedies, or findings.

Eight HTML snapshots are parsed with a deterministic non-DOM tokenizer. The parser records tag and attribute counts, heading and table structure, link and form counts, title length and hash, and bounded text-size measures. Scripts are never executed, no browser state is constructed, and malformed markup is not repaired into substantive meaning. Two of these snapshots are HTTP 403 bodies and remain access outcomes.

Four credentialed or lawful-access sources remain terminal boundary records. Wave 33 does not substitute a public catalogue, manufacture an empty response, or infer that no records exist.

Each parse row binds the source snapshot row, response bytes, parser profile, parser implementation hash, parse state, structural summary, limits, and zero-authority boundary. The nineteen parse objects are reused across the unchanged seven-route, thirty-eight-task, 153-use Wave 32 denominator.

A structural parse improves addressability. It does not establish a complete institutional denominator, authorize a cross-source join, adjudicate evidence, create estate adoption, promote a finding, modify the graph, or clear publication.
