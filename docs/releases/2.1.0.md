# Clifford Number 2.1.0

Release line: 2.1.0, the explorer release. Prepared on 22 October 2026 on the 2.0.0 cut.

This release changes the public explorer and the repository around it. It adds no research. The compiler, the ledgers, the hop rules and the constitution (BUILD-INSTRUCTIONS Section 1) are the same as in 2.0.0 and 1.3.0.

[The 2.0.0 note](2.0.0.md) said the public application was the same as in 1.3.0. That was wrong for the cut it described: the cut already carried the 1.4 explorer change (below), which no release note had recorded. This note records that change together with everything added on 22 October 2026. The note on 2.0.0 is corrected in place.

## The 1.4 explorer change the cut already carried

Commits `da06da21` ("Make the research field a continuous semantic aperture") and `e24f5bd9` ("Turn the research field into a dated evidence ecology"), both dated 12 October 2026, are the two commits of the never-merged 1.4 branch, cherry-picked onto the cut. They changed seventeen public files and had no release note. They:

- added a "Start with a person or organization" name search to the Explore controls (a datalist over the research-network nodes), a **Depth** slider whose stops are named Whole network, Neighborhood, Bounded surface and Evidence, and an **Evidence time** scrubber with play;
- added a "Documented activity" list to the field inspector: the dated ledger records of the selected object;
- kept the GPU field active at all four depth levels. 1.3.0 had used it only for the whole-network level and returned the stage to the SVG scenes when the reader zoomed in; since this change the SVG scenes are the fallback when WebGL is unavailable;
- replaced the 1.3.0 link particles with dated activity pulses derived from the participation rows (`buildEcologyEventModel` in `src/social-field.js`), and renamed the aperture heading to "Pick a person. Follow the public record.";
- rewrote the homepage copy and added two calls to action pointing at the explorer.

They did not change hop data, routes, receipts, the Route or Roster modes, or the standalone build. Everything the Explore tab does today is described under [The Explore tab](#the-explore-tab), which supersedes this list.

## The gate made reproducible

`npm run release:check` failed on the cut in two places (commit `58459f93f`). `finalize-release-artifact` refused the tree because the status-sovereignty and POOF release manifests pin `package.json` by hash, and `package.json` had changed four times after they were last generated. `validate-pages` pinned the 1.3.0 aperture heading that `da06da21` had renamed. The validator now accepts either heading (lines 254 and 352 of `tools/validate-pages.mjs`), and the twelve regenerated manifests, data and report files are committed. The commit records a clean `npm ci && npm run release:check` on OCTO-W03 (node 22).

Two Windows defects were fixed in the same pass:

- **25 builders and validators had a main-guard that is false on Windows** (`import.meta.url === \`file://${process.argv[1]}\``; `argv[1]` is a drive-letter path there). Nine compile-chain steps exited 0 without reading or writing anything: `build-report-frontier`, `render-report-frontier`, `build-next-ten-estates`, `build-estate-expansion`, `build-estate-frontier-surveys`, `build-estate-game-trails`, `build-estate-closures`, `render-estate-aperture` and `render-gametrail-aperture`; the other 16 are status-sovereignty RD-wave builders and validators. On Windows (node 24.19.0) each of the nine rewrites its outputs byte-identically to the committed files (commit `1047cd5d8`).
- **Seven passing tests were wired into `npm test`** that nothing had run: `constitution-gates`, `receipt-contract`, `topology-admission-frontier`, `reported-hop-evidence-upgrades`, `estates`, `estate-expansion` and `next-ten-estates`. `test/scheduled-crawl-promotion.test.js` now skips its two shell fixtures, naming the missing tool, on a host without `bash` or `jq`; CI on `ubuntu-latest` still runs all three (commit `456a44aa0`).

## The legacy SVG atlas and Evidence Overview retired

`explorer.html` loaded two atlases into one DOM node. `app.js` built the SVG representation ladder documented in 1.1.0 (corpus, machine, surface, route and evidence levels) inside `<section id="network-atlas">`, then marked the page ready; the Visual Aperture (`src/aperture-bootstrap.js`, `src/visual-aperture-part-11.js`) waited for that mark and replaced the section's contents with its own shell. The ladder therefore rendered for one frame on every load and was deleted. After that, every `app.js` selector into the section returned null and the ladder's entry points were no-ops. Two pieces survived outside the section but were wired to nothing: the orientation strip (whose copy described rings the live field never drew, and whose auto-dismiss hook nothing called) and the legacy Evidence Overview panel (whose "Visible objects" tab reported one row describing the destroyed view, and whose rows no longer selected anything).

Commits `236ebe7a0`, `d24df36c5`, `e2ff432bc` and `8794a5b50` removed the dead code rather than the aperture:

- `app.js` lost `initNetworkAtlas`, `mountAtlasLevel`, `renderNetworkAtlas`, `renderHopSpine`, the hover chip, the orientation strip, the legacy Evidence Overview model and renderer, `renderHome` and `renderHeroNetwork` (no call site, no target element), the `bindEvidenceActions` stub, the pin and focus bindings, the semantic-zoom thresholds and the hero and hotspot double writes: 4,059 to 1,820 lines. It no longer fetches `build/atlas-projection.json` (373,215 bytes) or `build/scout-report.json` (98,302 bytes), which nothing on the page read; both remain as data artifacts and `build:atlas-projection` still runs.
- `explorer.html` lost the legacy heading, the Research/Hops mode toggle, `#atlas-stats`, the toolbar, `svg#network-svg`, the hover chip, both legends, `#network-inspector`, the hop spine, `#atlas-orientation-strip` and `#evidence-overview`. The `#network-atlas` section keeps its id, empty, as the aperture's mount point.
- `styles.css` lost the orientation-strip, legacy-atlas and legacy-Evidence-Overview rules and twelve never-matched classes (most from a removed hero topology card, plus `.civic-boundary`, `.path-card` and `.case-receipt`). The public-data-boundary rules used `var(--mono)`, which only `home.css` defines; they now use `--font-mono`.
- The three tests that evaluated the deleted functions through `vm` were retired with them: `test/atlas-interaction.test.js` (281 lines), `test/atlas-semantic.test.js` (461) and `test/evidence-overview.test.js` (359). `test/route-modes.test.js` keeps its live desk and release-strip assertions. `tools/validate-pages.mjs` pins what the explorer now ships (the aperture mount, the desk, the evidence dialog, `routeModesModel`, `openReceiptDialog`, `inspectorBreadcrumbModel`) and refuses the legacy entry points if they return. `tools/build-standalone.mjs` stops embedding the two unread artifacts.

Nothing visible changed on a normal load, because the aperture had been mounting over all of it. Three things did change: the evidence-dialog breadcrumb no longer says "Research network / Dialog" for every receipt opened inside the aperture (it had been reading the dead ladder's frozen default selection); the try-example and case-focus buttons derive their counts from `build/surface-graph.json` instead of the literals 124, 16 and 10, and omit the count when no surface documents the focus; and the orientation strip and the legacy Evidence Overview panel are gone.

On the homepage (commit `6c3274023`), the 169 canonical overlay rows in `graph.json` (type `topology`, the actor-to-surface overlay projected from the bounded-surface ledger) had been falling through an unmapped-type default into the workflow-admission lane as a 169-record "Topology" mark and into the "392 documented records" total. They are now set aside before classification and reported as excluded; an unmapped edge type throws. Over the published graph the homepage reads 223 documented records across 8 marks (was 392 across 9). The "Plate A/B/C" evidence-inspection section, which drew three identical unlabelled dot grids with no receipts, is removed, and `home.js` stops fetching `build/hop-graph.json` and `build/surface-graph.json` (763,618 bytes it never read).

## The Timeline arrival mode

The explorer now opens on a ledger timeline (`src/visual-aperture-timeline.mjs`, `src/visual-aperture-timeline-runtime.js`, `src/visual-aperture-timeline.css`; commits `9be00e331` to `5214f1dd7`, `258d00ae5`, `d58b677f6`). The aperture's tabs are 01 Timeline, 02 Explore, 03 Route, 04 Roster; a URL with no `ap_` state opens the Timeline.

**What a mark is.** One ledger row: a participation row from `build/surface-graph.json` (in the surface-type view, one surface row). A mark sits on the lane of its person, organization or surface type at the row's documented date; its fill is the row's evidence class and its outline says whether the surface is hop-eligible. A row with a day, month or year date is drawn at that precision (month and year rows are widened to the period they name); a row with an end date is drawn as a span; an open-ended row is drawn to the edge of the axis; a row with no date is never placed on the axis and is listed instead. Rows that fall within a few pixels of each other fold into one "+N" object that still counts each row.

**What a column is.** One hop basis: a (day, surface) object from `build/hop-graph.json`, drawn as per-lane segments that touch only the lanes of that surface's participants. The surface is the column, so a route reads actor → surface → actor; no line is ever drawn between two people, and a column never crosses an uninvolved lane. The 95 hop bases in the release group into 19 (day, surface) objects on 18 days.

**What the roster block is.** A dense surface (20 or more actor rows; today exactly the Dialog public directory, 112 listed names, 113 rows) is one contained block with its count. No name on it gets a personal mark and no line joins any two of them. Its members pass the same filters as every other row: under the "official" evidence floor the block is not drawn (none of its rows is official), and the dropped rows are counted as filtered.

**Lanes.** The People view (default) gives a named lane to every actor documented on two or more surfaces (15 today) and puts everyone else in one strip, "People documented on one surface" (38 rows). Organizations and Surface types are the other two groupings. Up to 18 named lanes can be shown; the status line says when an added lane drops a default.

**Controls.** Lane grouping (People, Organizations, Surface types); year chips and All; "Add a lane" (a search over people, organizations and surface types); the Surfaces filter (all, hop-eligible only, context only); the evidence floor; "Mark a window", which dims rows outside a [from, to] window and never removes them ("N of M rows in window"); Reset. Ctrl or Cmd + wheel zooms the axis (a plain wheel scrolls the page); the overview strip under the axis carries the axis handles. Keyboard: Tab reaches one mark, then the arrow keys, Home and End walk the days and lanes; the lane labels are a second stop. Every mark, lane, column, block and fold has an inspector card with its role, window, evidence class, receipt buttons and actions (open the record, add lanes, route from here, open the roster view). The export packet, the saved-view workspace and "Copy exact view" work in this mode as in the others.

**URL keys.** `ap_time_by`, `ap_time_from`, `ap_time_to`, `ap_time_cursor`, `ap_time_lanes`, `ap_time_sel`, `ap_time_evidence` and `ap_time_hop`, written only when they differ from their defaults.

**Counts on the release data** (pinned in `test/visual-aperture-timeline.test.js` and `test/visual-aperture.test.js`): 286 rows (263 day, 20 span, 2 year, 1 open-ended, 0 undated); 95 hop bases into 19 surface-day objects on 18 days; default desktop People view: 15 named lanes, a 38-row strip, 1 roster block, 79 marks and 16 columns; at phone width 48 marks and 10 columns. The reserved selector `line[data-ap-time-pair]` is asserted absent: nothing draws a person-to-person line.

**Data handoff.** `app.js` exposes the surface, hop and receipt graphs and `graph.json` on `globalThis.__cliffordPublicData` before it marks the page ready; the aperture reads those first and fetches only when none is present (commits `4c218789b`, `5cd0afa5b`). This removes the aperture's 1.47 MB re-fetch of four JSON files on arrival. The aperture also publishes its selection on `globalThis.__cliffordApertureOrigin` (mode, object label, object id, a re-select function) for the receipt breadcrumb (commit `adbedcb89`).

**Smoke.** `tools/smoke-public-routes.mjs` adds a 320×568 viewport, the timeline-default and timeline-shared-view cases, a slow-data case that holds every JSON response 500 ms, and a post-load check: the active tab, at least 48 marks, one roster block naming 112, zero `line[data-ap-time-pair]`, no WebGL file fetched, no JSON fetched twice (commits `5214f1dd7`, `5cd0afa5b`, `c116ef759`).

## The Explore tab

The GPU field (`src/atlas-webgl.js` over `src/social-field.js`) keeps the 1.4 decision to stay active at all four depth levels when WebGL is available, with the SVG scenes as the fallback. The merge `12f71202f` ("Explore-field hygiene") changed what it shows:

- **Counts come from the ledger.** The composite heat (degree, clustering, surface, repeat and evidence weights) is gone as a visual channel. Node size and halo are the documented surface count for that object (participants, for a surface), with a legend label saying so; arcs keep their evidence-class colour. The tooltip count and the inspector count agree on every one of the 346 field nodes, and "no ledger rows" is said on exactly the 103 nodes that have none.
- **Evidence time is a window.** The single scrubber became a [from, to] window with two handles and an "All time" button. Out-of-window arcs and pulses dim and are never removed; the header reads "N of M rows in window", where M is the object's ledger row count; undated research arcs are never sliced. The 45-day pulse shoulder is gone: a pulse exists only inside its row's window, and a pulse bead rides the arc it claims.
- **Pause when not watched.** The render loop and the play clock run only while the stage intersects the viewport, the document is visible and the field is the active stage; `root.dataset.apertureAnimation` reports `running` or `paused`.
- **Reduced motion.** Play is off by default and never starts under `prefers-reduced-motion`; there is no flicker or wave.
- **Arcs open their row or claim.** A canonical overlay (topology) arc opens its participation row in the inspector (surface, role, window with precision, evidence class, receipts, an "Open public record" action). A research arc shows its claim, status, evidence and sources, then opens the catalogued claim in the evidence dialog with its receipts. This closes the ladder's regression gate "every rendered actor-to-actor abstraction expands to a named surface basis" on the live renderer.
- **Rows the field cannot draw are labelled, not omitted.** Every ledger row of an inspected object is listed, oldest first (the first ten open, the rest in a details element). The four rows on a surface the public graph carries no node for read "not drawn on the field (privacy guard)"; a dense-roster row reads "drawn as one contained roster object, not as an arc". Every receipt on a row is a button.
- **Arc factors now apply.** The renderer addressed arcs at a binding 3d-force-graph never sets, so the depth fade, hover dimming, time-window factor and selected-arc emphasis had silently done nothing. They are applied, and re-applied when the library finishes building its objects.

## The entity pages (in progress)

The entity pages (`#actor/`, `#organization/`, `#surface/`, `#chain/` and search) are being rewritten in parallel with this release as Workstream E of the 22 October specification. They are described here by contract, not by code, because they are not in this cut:

- the pages are fed from the same derived model as the Timeline (`src/visual-aperture-timeline.mjs`), with no second record-ledger module;
- each page shows fact chips with their denominators; a date-sorted ledger table (row number, date or window with precision, surface, role, organizations, evidence class, receipts in a details element) with a status line that is never silent; "Patterns in the rows" (surface-type counts, organization counts, hop partners with their basis day, then counted co-presence with dense surfaces excluded); type and year hash routes; the Dialog roster table sorted by "Also documented on"; "Copy ledger as text"; a single-lane mini timeline above each ledger table and an "Open in the timeline" button the aperture catches;
- search results carry fact lines; the "Structural context index" and "Factory Score" are removed and replaced with ledger facts; a machine-derived profile is labelled as such;
- `app.js` reads `globalThis.__cliffordApertureOrigin`, so a receipt opened from the aperture carries an honest breadcrumb.

Until that work lands, the entity pages are the 1.3.0 pages with the retirements above.

## What is not claimed

- **No new findings.** No research was done for this release. It adds no claim, surface, participation row, hop or receipt. Every count above is a count of the same 2.0.0 ledgers.
- **No outside review.** Every check, verdict and judgment in this release was made by the project's own agents and maintainer. No independent party has reviewed the explorer, the archive moves or this note.
- **GitHub `main` still serves 1.3.0.** This release lives on the 2.0.0 cut and its 22 October branches. The live site at `bigbirdreturns.github.io/clifford-number` and the public `main` branch do not change until the operator merges and publishes; the allowlist's `state` is still `candidate_until_protected_main_merge`.
- **No browser verification beyond the smoke tool.** The payload figures are file-size sums over the code path. The smoke tool was run headless against the served worktree during development (the commits name Edge); it runs with the GPU disabled, so the WebGL field is not exercised by the gate. The maintainer's Linux gate and browser check of the pages are still to come.
- **Open items carried forward.** The Explore tab ships two copies of Three.js (the vendored 0.186.0 module and the 0.183 copy inside the vendored 3d-force-graph bundle); the aperture has no translatable strings, so the Language selector translates only the chrome around it; the 18 classic aperture runtime scripts are loaded one at a time, in a fixed order, rather than bundled. The entity pages are not in this cut. The constitution gate's non-blocking warnings and the other open items listed in the [2.0.0 note](2.0.0.md#known-open-items) stand.

## Verify it yourself

```bash
npm ci
npm test
npm run release:check
```

`release:check` compiles the ledgers, runs the validators including the receipt contract and the constitution gates, runs the 114 test files, builds the Pages artifact and the standalones, and validates the artifact against the publication allowlist, which now reports version 2.1.0. A hostile stranger running those three commands from a clean checkout should reproduce the result (BUILD-INSTRUCTIONS rule 1.8).
