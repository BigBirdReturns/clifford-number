# Clifford Number 1.0.0

Clifford Number 1.0 is the first release line that binds the surface-hop compiler, receipt-backed reader, cases, dossiers, estate aperture, and game-trail aperture to one exact positive publication boundary. The release keeps the project name and accumulated provenance while separating authoritative ledgers, reproducible projections, custody-only material, and the deployed static artifact.

The release artifact is enumerated by `data/project/publication-allowlist.json` and content-addressed by `release-artifact-manifest.json`. The manifest records the source commit and tree, admitted build clock, every payload path, byte count, SHA-256 digest, aggregate payload digest, and observed performance budget. `deployment-sha.txt` is generated before validation and must match the deployed commit; the deploy workflow uploads no post-validation mutation.

Release 1.0 does not convert declared research frontiers into findings. NatSec100 canonical promotion, cross-case identity admission, external second-party review, and staged POOF publication remain governed by their owning records. Transport packages, recovery carriers, private/local support material, crawler intake, and nonpublic POOF projections remain in repository custody and outside the Pages artifact.

Reproduce the tested release from a clean checkout with:

```bash
npm ci
npm run release:check
```

Inspect `dist/release-artifact-manifest.json` for the exact source and payload identity produced by that command.
