# Preference Custody laboratory floor v12

Floor v12 composes the qualified thirteen-control v11 base with PC-14, provenance attack, detection, quarantine, rollback, clean replay, correction, abstention, and recovery equifinality. The v11 controls remain frozen and executable. PC-14 is admitted through a separate fixture, proof matrix, custody chain, refusal ledger, promotion boundary, and frontier transition.

The floor remains synthetic. It creates no graph effect, thesis evidence, named-system incident finding, attacker attribution, product-security verdict, manipulation claim, legitimacy verdict, public-authorization finding, or inference of intent.

## Composition

```text
Preference Custody floor v11

Preference Custody floor v12

```

The v12 compiler validates and hashes the complete v11 build before admitting PC-14. A new control cannot silently weaken the earlier exposure, option-set, mechanism, attrition, subgroup, authority, agenda, bargaining, succession, longitudinal, network, deliberative, or epistemic-quality controls.

## Qualified containment and recovery paths

The fixture preserves two pre-decision containment paths. Source spoofing fails authenticity checks before a decision. A hash-valid and signature-valid V1 packet fails semantic freshness and current-epoch authorization. Both artifacts are quarantined and replayed from clean V2 inputs without transient implementation exposure.

The fixture also preserves three post-decision rollback paths. Poisoned evidence, injected retrieval context, and a compromised signer each produce A0 before detection. The affected object is quarantined, the compromised checkpoint is rolled back, clean inputs are replayed, A1 is validated, and correction is issued where a decision entered the institutional record.

```text
pre-decision containment
≠ post-decision rollback

post-decision rollback
≠ successful replay

successful replay
≠ no prior consequence
```

## Cryptographic validity is not provenance sufficiency

Five worlds pass their observed hash and signature checks while failing another provenance state:

```text
poisoned content
injected retrieval context
stale semantic epoch
compromised signer credential
silent unauthorized substitution
```

The floor therefore preserves these objects separately:

```text
byte equality
signature validity
signer trust
trust-anchor state
semantic freshness
current-epoch authorization
content integrity
complete runtime lineage
```

A matching hash establishes equality with one registered byte sequence. It does not establish that the sequence is current, authorized, unpoisoned, complete, or relevant to the current decision. A valid signature establishes use of a credential, not the uncompromised status or continuing authority of that credential.

## Detection, quarantine, rollback, replay, and correction

PC-14 seals each recovery stage independently:

```text
detector signal and timing
→ affected artifact identity
→ quarantine scope
→ forensic snapshot
→ rollback to last-known-good state
→ clean-source reconstruction
→ deterministic replay
→ replay validation
→ correction and notification
→ final implementation consequence
→ residual uncertainty
```

Detection can end in safe abstention when no clean recovery source exists. Missing detection can leave a wrong version active. The floor therefore refuses detector presence as proof of recovery and detector silence as proof of cleanliness.

## Exact proposal and unchanged headline

All worlds retain the public 80/20 A-family headline. Their exact final states are:

A stable category-level result cannot establish exact proposal, implementation, or recovery continuity.

## Frontier transition

The broad v11 frontier:

```text
epistemic_adversaries_provenance_attack_and_recovery
```

is replaced by two narrower unresolved frontiers:

```text
cross_organizational_provenance_trust_federation_and_recovery
adversarial_attribution_incentives_and_recovery_externalities
```

PC-14 qualifies a single-system provenance and recovery state machine. It does not establish how trust, revocation, rollback, or incident authority should cross vendors, customers, regulators, clouds, model providers, or public institutions. It also does not identify attackers, incentives, deterrence, loss allocation, or externalized recovery burden.
