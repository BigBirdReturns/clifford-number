# Milestone M-01 — Bounded Estate Pass and Estate Aperture

**Milestone ID:** `estate-aperture-v1`
**Status:** completed at the declared pass boundary
**Repository train:** PR #99 → `main`
**Publication surface:** `estates/index.html`

## Completion statement

Clifford Number can now carry a durable domain estate from declared custody through a fully bounded acquisition pass and expose the result without manufacturing a story, relationship, score, or conclusion.

```text
source family
→ estate slice
→ durable estate
→ bounded parallel acquisition lane
→ closed task state with residual fog
→ candidate-only estate handoff
→ Estate Aperture projection
→ human evidence review
```

The milestone closes the work that had already been targeted and sequenced:

- 14 durable macro estates;
- 143 dependency-ordered tasks;
- 87 source-route uses across 66 route labels and 54 canonical source families;
- 34 shared-source infrastructure corridors;
- 14 deterministic candidate-only handoffs;
- one issue-linked closure record for each estate lane;
- one self-contained Estate Aperture for Pages and portable use.

## Acceptance boundary

A task is complete when the declared bounded operation has a result, residual fog, next transition, source or custody references, and an inference boundary. Only the final handoff assembly is `surface_complete`; the other 129 tasks remain `partially_searched` because real record acquisition, identity adjudication, chronology, and control work remain open.

This milestone does **not** claim that:

- any estate’s full evidentiary universe is complete;
- a portal is the underlying record;
- a name or brand match resolves a legal identity;
- a shared source corridor creates a subject relationship or Clifford hop;
- sequence establishes causation;
- a candidate packet is an approved report or publication.

## Demonstrated product behavior

The Estate Aperture has four semantic levels:

1. **Corpus** — all estates and shared acquisition infrastructure.
2. **Pipeline** — denominator, source, identity, temporal/null, and handoff stages.
3. **Task** — every bounded operation and its dependency order.
4. **Evidence** — the exact closure state, resolution, residual fog, next transition, references, and source-route metadata.

The view supports deterministic deep links, filtering without data deletion, keyboard operation, reduced motion, forced colors, mobile inspection, print, and a candidate-only JSON export carrying its interpretation boundary.

## New waterline

```text
current: bounded_candidate_handoff
next: human_evidence_review
```

Human review may promote individually receipted observations into typed case ledgers. The Estate Aperture itself cannot create claims, graph edges, causal conclusions, allegations, report approval, or publication approval.

## Integrity contract
