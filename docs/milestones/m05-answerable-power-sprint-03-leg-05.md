# M-05 Sprint 03 Leg 05 — Public-platform exit and operating sovereignty

## Question

What conditions make vendor exit a durable redistribution of operating power rather than a contract change, partial migration, replacement dependency, or formal ownership without practical sovereignty?

## Domain adapter

```text
APC-EXIT-01
Public Operating Sovereignty Covenant
```

The covenant requires the public body to preserve data, schema, workflow, users, permissions, evidence, security, accreditation, staffing, responsibility, continuity, modification, fallback, and post-exit governance. It also requires residual-custody reconciliation, represented-person standing, and an explicit value ledger.

## Positive control

### Homes for Ukraine Share

The official source set describes:

```text
Palantir Foundry-supported service
→ internal public build
→ migration of three years of operational data
→ user training
→ live transition
→ supplier-contract exit
→ continuing public operation
→ reported public code and data ownership
→ reported lower running cost
```

This supports one bounded R5 positive control.

It does not establish:

```text
complete incumbent deletion
independent performance or cost audit
universal Palantir substitutability
guest or sponsor co-governance
complete value recovery
```

## Controls

### NHS

Official transition and exit instruments show real product-level movement and contractual exit surfaces. They do not establish completed enterprise-level migration away from the larger Federated Data Platform relationship.

```text
transition contract
≠ completed migration

product movement
≠ enterprise exit
```

### NGC2

Separate divisional implementations and the Army Right to Integrate show counterfactual plurality and public-customer integration authority.

They do not establish that the common data baseline, interfaces, accreditation, deployment knowledge, or every critical component is practically substitutable.

```text
program plurality
≠ component substitutability
```

## Governing fault lines

1. Formal ownership is not operating capacity.
2. Product exit is not enterprise exit.
3. A new vendor can reproduce dependency.
4. Cutover does not prove deletion or residual-custody closure.
5. Public operation does not prove democratic co-governance.
6. Reported savings do not close a full value ledger.
7. Multiple vendors do not prove every common layer is substitutable.
8. One successful transition does not prove durable sovereignty after staff, policy, or supplier change.
