# Counter-Selector artifact-readiness method

## Purpose

Wave 02 tests whether the thirty source-routed objects installed by Wave 01 contain the **bounded work artifacts** required for blind-first review. It refuses to convert a K0 record, source summary, role label, later outcome, or policy architecture into an operator artifact.

The distinction is structural:

```text
source route
≠ work artifact
≠ blind packet
≠ operator finding
≠ consented field test
```

A qualifying artifact must preserve a bounded object or decision record, provenance and custody, a date or version, the task or gate, an observable state transition, and explicit limits or falsifiers.

## Audit sequence

```text
Wave 01 source-routed object
→ inspect observed_artifact_refs
→ classify the reference type
→ refuse source identifiers as artifact substitutes
→ freeze class-specific acquisition requirements
→ assign one object from every class to each balanced batch
→ acquire underlying object and receipt
→ remove biography and status cues
→ create blind packet
→ independent review
```

Wave 02 does not create blind packets by paraphrasing source summaries. Where the underlying object is absent, the correct result is `artifact_acquisition_required`, not a zero score and not negative capability evidence.

## Balanced acquisition

The queue contains five batches of six objects. Every batch carries one object from each Wave 01 denominator class. Batch order creates no merit, priority, or publication status. Failed acquisitions, inaccessible objects, privacy blocks, and bounded non-links remain in the denominator.

## Identity minimization

Before blind review, remove public labels, person and institution names, title, employer, jurisdiction, source identifiers, denominator class, matched-control identity, politics, and status metadata. Retain the task, operating requirements, artifact bytes or normalized extract, bounded chronology, state transition, failure or correction trace, limits, counterevidence, and falsifier.

## Authority ceiling

```text
missing artifact ≠ low capability
policy existence ≠ observed repair
negative control ≠ false person
artifact readiness ≠ operator score
acquisition queue ≠ permission to contact
acquisition queue ≠ consent
acquisition queue ≠ field-test authorization
```

No candidate advances to `CS-FT-01` until a qualifying artifact, identity-minimized packet, independent review, consent, bounded scope, stop rule, and clean exit exist.
