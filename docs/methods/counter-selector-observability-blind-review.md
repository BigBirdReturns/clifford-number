# Counter-Selector observability blind review

Wave 27 reviews the two Batch A observability packets without treating living subjects, source richness, or public correction as selection authority.

## Procedure

1. Preserve the source-to-identity map in the source contract.
2. Derive a packet containing only the task, requirements, chronology, observable transition, support context, counterevidence, and falsifier.
3. Remove names, project names, employers, sponsors, platform names, URLs, source identifiers, status labels, and prior class metadata.
4. State that identity blindness is not achieved when the artifact chronology remains inferable.
5. Run an artifact-validity pass and a separately framed adversarial-countermodel pass.
6. Restore the public source map only after both passes are recorded.
7. Localize person-versus-function and publication-versus-handoff disagreements rather than averaging them.
8. Complete the visible support ledger before considering support-adjusted surplus.
9. Require external review, consent, and a direct resumability or handoff receipt before any field test or promotion.

## Decision boundaries

- A team reversal is not automatically person-level exception handling.
- A public mistake admission is not universal model elasticity.
- A security advisory, patch, release, or upgrade guide is not an independent handoff.
- Paid work, sponsors, community labor, external research, AI assistance, and platform infrastructure must remain in the support ledger.
- Related software projects do not establish materially unrelated cross-domain transfer.
- Open-source publication and credit do not by themselves establish non-zero-sum orientation.
- Two same-system passes are procedural separation, not external independence.
- A living source subject creates no contact authority.
