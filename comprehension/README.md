# Phase-0 comprehension harness

This directory is a local, versioned evaluation instrument. It is not a
reader-facing release, newsroom mode, a connection checker, or a source of
graph assertions.

The first route deliberately uses the Dialog roster because it tests a hard
boundary already present in the corpus: a dense, receipted membership record
can be meaningful structural context while remaining ineligible to create a
pairwise Clifford hop. The route must terminate in `bounded_structural_context`
and `graph_effect: none`.

## Operating boundary

- Do not link this material from the public home page or connection checker.
- Do not use its copy as quotable or publication-ready narration.
- Do not add Dialog participation to pathfinding, scoring, or printed routes.
- Keep `reported` and `primary_public` receipt classes visible and separate.
- A session validator can return `READY_FOR_ADJUDICATION`, `FAIL`,
  `INCONCLUSIVE`, or `INADMISSIBLE`; it never returns `PASS`.

The route contract is checked against the current ledgers and compiled hop
graph by `node test/comprehension-protocol.test.js`. A test result establishes
only that the harness is structurally constrained. Independent comprehension
remains outside Phase 0 and requires an evidence-firewalled human session
followed by separate adjudication.
