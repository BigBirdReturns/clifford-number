# Allocator-war lawful join requirement fan-out Wave 35

Wave 35 consumes only the permanent Wave 34 lawful-join contract ledger. It does not revisit source discovery, parse source bytes, infer institutional semantics, or perform a network request. Each of the seven Wave 34 join contracts becomes one estate-owned queue, and each of its thirty-one unsatisfied institutional requirements becomes one deterministic acquisition task.

The task identity is derived from source join order and source requirement order. Each task carries the exact source join reference, requirement reference, estate owner, route class, access class, target row, completion test, refused substitution, source receipt set, schema-adapter set, candidate-key classes, and cryptographic custody hashes. A change to any source join or requirement therefore reconstructs only the affected queue and remains observable as generated drift.

Access classes remain separate. Twenty-five tasks permit public or separately authorized acquisition, three permit public or lawful case access, and three protected-personnel tasks remain bounded to authorized lawful access. Public aggregates, selected public case reports, category membership, and inferred identity may not substitute for the protected personnel roster, comparator, reason, appeal, correction, or outcome records specified by Wave 34.

Task admission is routing custody. It is not an acquisition result, requirement satisfaction, join authorization, complete denominator, evidence adjudication, estate adoption, finding, graph edge, or publication clearance. Wave 35 emits no same-wave acquisition result and performs no network request.
