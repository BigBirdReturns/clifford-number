# M-05 Sprint 03 Leg 05 — Public-platform exit and operating sovereignty

## Question

What makes a platform exit a durable redistribution of operating power rather than a contract change, a product migration, or a new dependency?

## Domain adapter

```text
APC-EXIT-01
Public Operating Sovereignty Covenant
```

A public institution reaches R5 only when it can operate, inspect, modify, govern, replace, and terminate the practical operating layer while preserving service, evidence, security, responsibility, and meaningful alternatives.

## Three bounded systems

### Homes for Ukraine Share

The positive control joins:

```text
Palantir-hosted emergency service
→ in-house public build
→ three years of operational data migrated
→ user research, quality assurance, and training
→ service cutover
→ supplier-contract exit
→ continuing public operation
```

This supports a bounded observed R5 result.

It does not yet close:

```text
complete supplier-side deletion
all derivative and backup treatment
independent long-run performance and cost audit
resilience after staff or administration change
guest and sponsor co-governance
R7 value recovery
```

### NHS bounded transitions and continuing enterprise platform

Formal transition and exit instruments exist for bounded Foundry-supported services. A separate, larger Federated Data Platform award and continuing enterprise platform also exist.

Therefore:

```text
product transition
≠ enterprise exit

exit contract
≠ completed migration

formal public data rights
≠ practical independent operation
```

### NGC2 component plurality

The Army preserved multiple prototype teams and divisional implementations while assigning an Anduril-led common data baseline and differentiated Palantir and Raft roles.

Therefore:

```text
program plurality
≠ common-component substitutability

public integration authority
≠ completed vendor exit

alternate stack
≠ replacement of every shared layer
```


## Pilot packet

A valid R5 claim requires:

- incumbent and replacement entities;
- contract, deployment, transition, cutover, and termination dates;
- complete functional and responsibility matrix;
- data, schema, lineage, model, interface, workflow, and log inventory;
- source, escrow, documentation, license, and IP rights;
- security, accreditation, continuity, and incident records;
- staffing, skills, support, budget, and succession plan;
- rehearsals, failures, fallback, and rollback;
- pre/post performance, cost, error, and user outcomes;
- residual access, deletion, derivative, and processor audit;
- represented-person and operational-user voice;
- separate R6 governance and R7 value-distribution instruments.

## Current result

```text
highest observed level: R5
one complete domain answer observed: false
works standard met: false
```

The strongest result is that a bounded public institution can rebuild, migrate, cut over, end a supplier relationship, and continue operating a consequential service.

The largest open join is whether the exit remains durable after turnover and whether residual custody, independent outcome evidence, represented-person authority, and value distribution are closed.
