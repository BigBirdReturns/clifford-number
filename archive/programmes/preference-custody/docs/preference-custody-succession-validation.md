# Preference custody: model, metric, policy, and validation succession

This candidate-only laboratory supports issue [#594](https://github.com/BigBirdReturns/clifford-number/issues/594). It closes a succession boundary: a validation result belongs to the exact runtime artifact, metric, benchmark, policy, and scope preserved by its receipt. A numerical badge cannot identify or authorize a changed successor by itself.

The fixture is synthetic. It creates no graph effect, thesis evidence, real-world causal conclusion, stale-badge finding, unvalidated-deployment finding, product-safety verdict, preference-change finding, manipulation claim, or inference of deceptive intent.

## Frozen baseline

The baseline system seals:

```text
model-v1
prompt-v1
retrieval-v1
postprocess-v1
metric-v1 / one-minus-mae / metric-code-v1
policy-v1 / threshold 0.70 / select_message
benchmark-v1 / 2026-Q1
validation-v1 / score 90% / pass threshold 85%
```

Every succession world displays the same public headline:

```text
validated_accuracy = 90%
```

The worlds differ in runtime identity, metric, policy, validation receipt, comparability evidence, and deployment consequence.

## Six succession worlds

### Exact artifact and scope replay

The runtime artifact, metric, policy, benchmark scope, and validation receipt remain unchanged. The baseline receipt can support the exact successor because there is no successor difference to bridge.

### Runtime successor inheriting the old badge

The model, prompt, and postprocessor change. No new validation is performed. The 90 percent baseline badge remains visible, but it is not bound to the successor runtime. The predictive claim and deployment are blocked.

### Changed metric with a current score and no crosswalk

The runtime and policy remain unchanged. A new metric produces a current 90 percent result, but no crosswalk establishes comparability with the baseline metric. The current result is usable within its own bounded scope. It cannot support a continuity claim that the two 90 percent scores measure the same thing.

### Changed policy inheriting the predictive badge

The runtime artifact and metric remain exact, so the predictive receipt still describes the predictor. The deployment policy changes from message selection at a 0.70 threshold to automatic targeting at 0.55. Without a consequence test for the new policy, predictive validation remains valid as predictive evidence but cannot authorize the changed deployment policy.

### Fully revalidated successor

The runtime artifact, metric, and policy all change. A new benchmark receipt, metric crosswalk, and policy consequence test are sealed. The successor can carry a bounded current and continuity claim under the new receipt. It does not become the baseline artifact.

### Failed revalidation with an old public badge

A changed runtime receives 75 percent against an 85 percent pass threshold. The failed receipt is preserved. The old 90 percent badge does not transfer. Deployment is blocked and rollback is required.

## What the control proves

The same public 90 percent headline is compatible with:

```text
exact valid inheritance
unvalidated runtime succession
current but noncomparable metric validation
valid predictor with an unvalidated deployment policy
fully revalidated bounded succession
failed revalidation and rollback
```

The executable refusal rules are:

```text
validation binds exact artifact, metric, policy, and scope
runtime change requires revalidation
prompt, retrieval, or postprocess change requires revalidation
metric change requires new validation and a comparability crosswalk
policy change requires consequence validation
same headline ≠ same measurement or scope
old badge cannot authorize successor
failed revalidation = negative evidence, not missing data
rollback or abstention preserves the failed result
publication claim requires current receipt and version
```

## Custody chain

Every succession world emits a SHA-256 hash-linked chain:

```text
baseline artifact, metric, and policy sealed
→ baseline validation receipt recorded
→ successor artifact, metric, and policy sealed
→ lineage diff recorded
→ validation action and receipt state recorded
→ metric crosswalk and policy-test evidence recorded
→ claim eligibility resolved
→ deployment, rollback, or abstention resolved
→ interpretation sealed
```

The baseline receipt cannot overwrite the successor identity. A new score cannot overwrite the metric definition. Predictive accuracy cannot overwrite policy-consequence evidence. A failed revalidation cannot disappear because a previous public badge remains more favorable.

## Real-case evidence floor

A real deployment requires:

```text
runtime artifact identity and hashes
model, prompt, retrieval, and postprocess versions
benchmark identity and data window
metric definition, code, and version
policy action, threshold, and consequence
baseline validation receipt
successor lineage diff
new validation receipt or explicit absence
metric crosswalk and baseline when changed
policy consequence test when changed
public badge claim scope and receipt
deployment, rollback, or abstention receipt
```

This is particularly important for synthetic-audience and decision-support systems that continuously change model provider, prompt construction, persona generation, retrieval, weighting, postprocessing, metric definitions, or deployment policy while retaining one stable marketing number.

## Promotion boundary

This control does not establish that Electric Twin, News UK, Dentsu, any vendor, any publisher, or any named institution reused stale validation, changed a system without revalidation, or deployed after a failed test. A real case needs versioned artifacts, exact receipts, a lineage diff, and the deployment consequence before validation continuity or failure can be attributed.
